# 多 Agent 并行生图规范

用于阶段 2：用户确认第 1、2 页，并明确选择多 Agent 并行制作剩余页面后读取。

并行只加速页面制作，不改变已确认的分页、文案、视觉模板和质量标准。主 Agent 负责设计契约、任务拆分、合并与最终交付；子 Agent 负责指定页面的制作、自检和修复。

## 启动条件

同时满足以下条件后才能启动子 Agent：

1. 页面结构已经确认；
2. 第 1、2 页的视觉已经确认；
3. 用户明确选择多 Agent 并行；
4. 主 Agent 已读取当前任务需要的生图规范、视觉语义规范和所选模板规范；
5. 当前环境支持启动子 Agent。

用户未明确选择并行时，不得启动子 Agent。当前环境不支持并行时，说明限制并等待用户同意改为串行。

## 主 Agent 先锁定设计契约

分配任务前，主 Agent 必须建立所有批次共同遵守的设计契约，至少包括：

- 画布尺寸、页边距、页脚位置和页码格式；
- 字体、字号层级、行高、颜色、边框和间距；
- 公共 CSS、公共组件和所选模板文件；
- 每页标题、完整文案、信息关系和页面顺序；
- 用户图片的落位、宽高比和裁剪限制；
- 输出目录、批次文件名和最终图片命名规则；
- 自动检查命令与人工检查清单。

设计契约建立后，子 Agent 不得自行改变。需要修改分页、文案或视觉系统时，停止对应批次并交回主 Agent 处理。

## 拆分任务

- 根据剩余页数、信息密度和关系复杂度拆成 2 至 3 个批次；不要只按页数机械平均。
- 每个页面只分配给一个子 Agent，明确页面编号和文件所有权。
- 流程图、复杂比较、长表格等页面计为高复杂度；普通文本页和简单并列页计为低复杂度。
- 保留一个执行槽给主 Agent 进行协调、检查和合并；不要耗尽全部并发槽。
- 子 Agent 分别写入独立批次文件，禁止同时修改主 HTML、公共 CSS 或同一输出文件。

推荐目录：

```text
work/
├── shared.css
├── batch-a.html
├── batch-b.html
└── batch-c.html
```

公共样式由主 Agent 创建并锁定。每个批次文件应能独立打开、渲染和检查；不要只交付无法单独验证的 HTML 片段。

## 子 Agent 任务包

主 Agent 给每个子 Agent 的任务必须包含：

1. 负责的页面编号与顺序；
2. 每页不可删改的完整文案；
3. 页面中的比较、顺序、映射、层级、因果或循环关系；
4. 公共样式与模板路径；
5. 独立批次文件和渲染输出路径；
6. 必须读取的规范文件；
7. 自动检查命令和人工审查要求；
8. 禁止修改的文件与允许修改的范围。

任务说明不得只写“制作第几页”，必须让子 Agent 能在不猜测设计规则的情况下独立完成并验证。

## 子 Agent 必须读取的规则

每个子 Agent 开始制作前，必须读取并遵守：

- `references/image-generation.md`；
- `references/visual-semantics.md`；
- 用户选择的模板规范；
- 主 Agent 提供的设计契约和页面任务包。

子 Agent 既负责制作，也负责审查和修改。不得把未经渲染或未经检查的页面交回主 Agent。

## 外部 skill 边界

子 Agent 不得调用 `layout-qa`。
子 Agent 必须按本文件、本 skill 的图片生成规范、自动检查脚本和最终 PNG 目检完成自检。
如发现布局问题，直接修改卡片 HTML/CSS 并重新渲染，不转交给外部布局审查 skill。

## 子 Agent 自检与修复循环

每个子 Agent 完成批次后，按以下顺序循环执行，直到通过：

1. 渲染自己负责的全部页面；
2. 运行自动布局检查；
3. 查看实际 PNG，而不是只检查 HTML 或 DOM；
4. 按完整检查清单逐页审查；
5. 修改发现的问题；
6. 重新渲染并重新检查。

自动布局检查至少运行：

```powershell
node scripts/check_card_layout.mjs batch.html --min-footer-gap 24 --max-empty-ratio 0.10
```

两个参数只设置主体到页脚的最小间距和异常空白比例，不代表只检查这两项。脚本输出的其他错误和警告同样必须处理。自动检查不能替代人工视觉审查。

### 完整检查清单

#### 内容保真

- 标题、正文、姓名、账号、日期、数字、代码、引用和链接完整；
- 页面顺序、序号、模块数量与确认稿一致；
- 不擅自删减、改写或补充事实；
- 用户图片落位正确，保持原始内容和宽高比，未经允许不裁剪。

#### 空白与密度

- 主体到页脚的异常空白通常不超过画布高度的约 10%；
- 不使用空容器、无信息装饰或无意义色块规避空白检查；
- 模块内部不能明显空旷；放大模块时同步放大字体、图示、行距或有效内容；
- 页面过密时先调整信息结构、栏宽、字号和段落分组，不擅自删减独立信息。

#### 溢出、裁切与重叠

- 所有可见文字、容器、线条、图标、图片和页脚均在画布内；
- 没有文字溢出、截断、遮挡或非预期换行；
- 模块之间没有非预期重叠；
- 主体与页脚至少保持设计契约要求的间距。

#### 可读性

- 标题在缩略图下仍可辨认；
- 正文字号、行高和对比度适合手机阅读；
- 中英文、代码和链接的换行自然；
- 不出现孤立短词、拥挤表格或需要猜测的阅读顺序。

#### 关系语义

- 表格、流程、时间线、映射、层级、比较和循环符合源材料中的真实关系；
- 箭头只用于具有方向、顺序或因果的关系；
- 连线附近的动作、条件或传递内容标注清楚；
- 辅助文字通过容器、对齐、编号或连线明确绑定到对应对象；
- 图示没有改变源材料的顺序、因果、范围或比较口径。

#### 视觉一致性

- 字体、颜色、边框、圆角、间距、页码和页脚与已确认试做页一致；
- 同类信息使用一致的视觉语法；
- 不添加与模板冲突的渐变、阴影、插图或装饰；
- 不因个人偏好重新设计公共组件。

如果连续修改仍无法通过，子 Agent 必须向主 Agent 报告具体页面、检查结果和阻塞原因，不得把问题页面标记为完成。

## 子 Agent 交回内容

每个子 Agent 完成后向主 Agent 提交：

- 负责的页面编号；
- 批次 HTML 路径；
- 渲染图片路径；
- 自动检查结果；
- 已完成的人工检查；
- 已知问题；没有问题时明确写“无已知问题”。

## 主 Agent 合并与终审

主 Agent 不直接信任批次的“已通过”结论。合并后必须：

1. 按页码顺序合并所有页面；
2. 确认公共 CSS 和模板没有被子 Agent 私自修改；
3. 对合并后的完整 HTML 重新运行自动布局检查；
4. 重新渲染全部页面；
5. 查看全部最终 PNG，按同一份完整检查清单逐页终审；
6. 对照阶段 1 的确认稿检查内容覆盖度；
7. 修复跨批次不一致、页码错误和合并后产生的问题；
8. 全部通过后再向用户展示完整轮播。

子 Agent 的检查不能替代主 Agent 的最终责任。任何批次失败、缺失或不一致时，由主 Agent 修复、重新分配或接管；不得交付残缺结果。
