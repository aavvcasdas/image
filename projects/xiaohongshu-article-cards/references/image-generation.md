# 图片生成规范

用于**阶段 2：生成图片**。页面结构已获用户确认后读取本文件；若材料包含比较、顺序、映射、层级、因果或循环等关系，同时读取 [视觉语义规范](visual-semantics.md)。


## 页面放不下时

按以下顺序处理，**不得**因模板固定模块数而删去材料中的独立信息：

1. 增加页数或拆成连续页（若增页会改变结构，先回到阶段 1 征得用户同意）；
2. 改变信息结构、栏宽、字号和段落分组；
3. 合并真正重复的表达；
4. 仅在用户同意后删减次要内容。

## 关系与结构表达

材料含比较、顺序、映射、层级、因果或循环时，严格按 [视觉语义规范](visual-semantics.md) 选择表格、时间线、流程、层级、比较卡或普通文本模块。

- 每个视觉关系都必须有可识别的关联对象和关系含义；
- 不要为了「更像信息图」而添加无源材料的箭头、连线或虚构分类；
- 分支、循环、双向关系分别呈现，不把多段含义堆在一根悬空线旁。

## 空白与密度

- 主体到页脚的异常空白通常不应超过画布高度的约 10% ；
- 主体到页脚，或主要模块之间的无信息空白，超过画布高度约 10% 时必须人工确认；超过约 14% 时不得交付，必须先修复；
- 不得为凑版式留下无信息量的装饰空白；
- 内容较少时，优先放大标题、核心模块和行距，其次生成适配段落主题的插图，而不是留大块空区。
- 修复异常空白时，优先整体放大现有信息组：模块高度、标题字号、正文字号、行距、内边距一起调整；不得只拉大空框；
- 调整模块垂直分布，让内容更均匀；
- 可用原文已有关系补成结构，例如对比条、流程条、分区标题、总结条；不得为填空白虚构信息；
- 放大核心模块时，模块内字体也需要跟着放大，不让模块内部太空旷。

## 可读性与保真

- 标题在缩略图下仍可清晰辨认；
- 检查溢出、裁切、重叠、页脚间距；
- 所有序号、箭头、模块顺序与已确认结构一致；
- 用户图片保持原始内容与宽高比，为适配版面可整体按比例放大缩小；
- 按阶段 1 已确认的拆分方案核对覆盖情况。

## HTML 工作流

使用 HTML 制作时：

- 每个页面使用 `.card` 类；
- 供版面检查的主体、内容终点和页脚分别标记 `data-card-content`、`data-content-end`、`data-card-footer`；
- 按需运行：

```powershell
node scripts/check_card_layout.mjs cards.html
node scripts/render_cards.mjs cards.html output-directory card
```

脚本不能替代人工内容与视觉检查。

## 验收边界

卡片渲染后的布局、溢出、裁切、重叠、页脚间距和异常空白检查，均属于本 skill 的内部验收。
使用 `scripts/check_card_layout.mjs`、实际 PNG 查看和本文件检查清单完成。
不要调用 `layout-qa` 作为默认检查流程；只有用户明确要求“使用 layout-qa”或“对我提供的截图做红框/圈注标注审查”时才允许切换。

## 修改与回退

| 用户反馈 | 处理方式 |
|---|---|
| 改文字、增删页、调整分页 | 回到阶段 1，重新提交拆分方案并确认 |
| 只改配色、版式、密度、关系画法 | 重做试做页（第 1–2 页），再次确认后继续 |
| 换模板 | 重做试做页，再次确认后继续 |
